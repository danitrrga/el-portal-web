Write the Spanish page header, the six tag labels, and the first half of the
entries array (most recent first, matching the English ordering) into
`src/messages/es/changelog.json`.

Copy `version`, `date`, `tags` and `isRelease` across UNCHANGED. They are shared
data. Translating an ISO date or a tag key is the specific mistake plan 07-12's
structure exists to prevent, and it would make the two locales disagree about
when something shipped.

Translate `title`, `body`, and each bullet's `lead` and `body`. Bullet leads are
short bolded feature names and are the most compressed strings on the page —
prefer a compact Spanish term over a literal translation.

Apply `SPANISH-VOICE.md`: no written subject pronoun, no `usted`, no formal `su`,
no exclamation marks, none of the 16 anti-words. Where a sentence addresses the
reader, `tu` conjugation; where it describes what the product now does, plain
third-person product description. Do not contort a product description into
second person just to demonstrate the register.

Resolve product nouns through `src/messages/GLOSSARY.md`. Changelog entries name
product surfaces constantly, so this is the page where an invented term is most
likely and most visible. `Trends`, `Dashboard`, `Cinema` and `Pulse` stay
English; `Versiones`, `Ciclo`, `Dia`, `Habitos`, `Objetivos`, `Puntuacion` and
`Archivos` translate.

Technical terms that appear as code or identifiers in the English entries stay as
they are. A changelog that translates an API name is documentation that lies.

Keep entry ORDER identical to English. Ordering is semantic here — the array is a
reverse-chronological release history, and plan 07-12's `2.0.0` anchor rule
depends on position.

Because Gate 2 escalates to full enforcement as soon as this file has any key, do
not expect a green gate until Task 2 completes the file. That is expected
mid-plan, not a defect.
