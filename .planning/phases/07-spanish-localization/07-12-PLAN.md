<objective>
Move every changelog entry out of `changelog/page.tsx` into the English
catalogue, and extend the `el-portal-changelog` skill so future syncs write both
locales.

Purpose: research §6 identifies the changelog as the only surface in this phase
with a *recurring* cost. The skill syncs new entries from the app repo
continuously, so without a translation step the Spanish changelog decays from the
first sync onward — while still looking complete, which is worse than visibly
missing. D-09 makes extending the skill a named part of this phase's scope for
exactly that reason.

At roughly 165 strings the entries are also the largest single translation job in
the phase, so translation is split out into plan 07-14. This plan does the
mechanical half and defines the catalogue shape 07-14 and every future sync write
into. Getting that shape complete matters more than usual here: 07-14 translates
against this plan's output, so any field this plan forgets is a field 07-14 will
never translate.

COUNT DISCIPLINE. An earlier draft of this plan asserted 35 entries and embedded
`if (e.length !== 35)` as a hard gate. The tree has 33 (`grep -c 'version:'
src/app/changelog/page.tsx` -> 33, versions 2.0.28 down to 1.0.0), so that plan
could not pass its own verification. The fix is not a corrected constant — it is
Task 1's first step, which measures the count from the source and writes it to a
file both this plan's gate and plan 07-14 read. A number typed into a plan rots;
a number derived from the artifact cannot.

Two structural decisions make the recurring cost survivable and are taken here
rather than left to the executor: dates are stored once as ISO values and
formatted per locale, and tags are a closed key set. Both remove a whole class of
string that would otherwise need translating on every single sync.

Output: a complete `changelog` English namespace, a locale-aware date render
path, a derived entry-count artifact, and an updated skill.
</objective>
