<objective>
Make the existing test and CI machinery locale-aware **before** any Spanish copy
is written, so every translation plan in Waves 3-4 lands inside a harness that
already sees its route.

Purpose: `e2e/support/pages.ts` currently holds 8 flat English paths, and
`containment.spec.ts`'s `KNOWN_UNFIXED` entries are keyed by exact route string —
`/pricing` does not cover `/es/pricing`. If this stays as-is until the end of the
phase, every translation plan is authored blind and the Spanish overflow defects
all surface at once in a single unreviewable verification pass. Extending the
harness first turns "does this Spanish string fit?" into a per-plan question with
a per-plan answer.

The three gates mechanise what a human reviewer cannot reliably catch across
~390 strings: a register leak (`usted`), a silently missing or orphaned key, a
dropped ICU placeholder, and a `next/link` import that would strand a Spanish
visitor on the English tree.

Output: a 16-route harness with reconciled suppressions, and one gate script
wired into the existing `quality` CI job.
</objective>

  <action>
Write `scripts/i18n-gates.mjs` as one Node script exposing three independent
checks, each reporting every violation it finds with file path and key path
before the script exits non-zero. A gate that stops at the first failure makes a
390-string catalogue take twenty CI runs to clean up.

GATE 1 — REGISTER. Walk every value in every `src/messages/es/*.json`, including
nested objects and array members, and hard-fail on: `usted`, `ustedes`, and a
written `tu` subject pronoun. Match with word boundaries and case-insensitively.

Distinguishing the banned subject pronoun from the sanctioned possessive is the
whole difficulty of this gate and must be handled deliberately: the possessive
`tu` (`tu primera Version`) is REQUIRED by the register, while the subject
pronoun (`Tu empiezas`) is banned. The practical discriminator is that the
subject pronoun carries the accent and the possessive does not, so hard-fail the
accented form as a standalone word and leave the unaccented form alone. Document
that discriminator in a comment in the script, because a future reader will
otherwise "fix" it into uselessness.

Two tokens must NOT be in the hard-fail list, per `SPANISH-VOICE.md` and
07-RESEARCH.md section 7:
  - `vosotros` is explicitly ALLOWED. Including it would fail the project's own
    sanctioned copy.
  - `su` / `sus` is ADVISORY ONLY — it is also the legitimate third-person
    possessive. Print it as a warning with key path and exit code 0 for that
    check alone.
Also warn (do not fail) on any Spanish anti-word from `SPANISH-VOICE.md`, and
hard-fail on `!` or the inverted opening exclamation anywhere in an `es` value,
since exclamations are banned site-wide in both locales.

GATE 2 — CATALOGUE PARITY. For each namespace, flatten `en` and `es` to dotted
key paths and evaluate translation status from the catalogue itself, with no
external allowlist:

  - `en` empty and `es` empty            -> pass silently (namespace not started)
  - `en` has keys and `es` is exactly {} -> WARN "namespace not yet translated",
                                            name the key count, exit code
                                            unaffected
  - `en` has keys and `es` has SOME keys -> ENFORCE fully; every missing key,
                                            type mismatch, array-length mismatch
                                            or placeholder-set mismatch is a
                                            hard failure

This inference is what replaces a shared allowlist. It has the property that
matters: a namespace nobody has started is quiet, and a namespace someone is
halfway through is loud. Partial translation is the actual risk — it is the
state that looks complete and is not.

KEY IDENTITY IS BIDIRECTIONAL, and this is the direction the cross-AI review
flagged as the gate's blind spot. `en ⊇ es` must be enforced explicitly, not
just `es ⊇ en`:

  - a key in `en` that is missing from a non-empty `es`  -> hard failure
  - a key in `es` that does NOT exist in `en`            -> hard failure

The second is the one that quietly matters: when an English key is deleted (a
section removed, a component rewritten) the Spanish mirror keeps rendering a
string nothing reads, and every "is Spanish complete?" check still passes. Treat
an orphaned `es` key as a defect, not as harmless residue — the whole point of
key identity is that the two files describe the same site.

Evaluate this leniently in exactly one state: when `es` is exactly `{}`, the
namespace is PENDING and neither direction is checked. That is what makes the
incremental Wave 3 -> Wave 4 namespace filling possible, and it is the only
exemption.

Extract ICU placeholders with a regex over `{name}` and `{name, plural, ...}`
opening tokens and compare as SETS, since order legitimately differs between
languages. Research section 5 names placeholder parity as the single
highest-value quality gate available here — a missing `{count}` is a runtime
error, not a typo.

Add a `--strict` flag that upgrades the "not yet translated" warning to a
failure. The final verification plan uses it to assert that no namespace was left
behind; nothing else does.

GATE 3 — LOCALE-AWARE LINK. Fail on any file under `src/` that imports from
`next/link` AND contains an internal href — an `href` whose value starts with `/`
either as a string literal or inside a template literal that does not begin with
a protocol. Absolute external URLs (the `APP_URL` constants in `Navbar.tsx` and
`pricing/page.tsx`) legitimately keep `next/link`, so the gate must key on the
href shape, not on the import alone. Report file and line.

Without this gate the failure is invisible in review and obvious to a user: a
Spanish visitor on `/es/pricing` clicks a nav link and lands on the English
`/manifesto`, silently leaving the Spanish tree.

Register the script in package.json as `i18n:gates`, and the strict form as
`i18n:gates:strict`. Do not wire either into `npm run build` — CI runs the
default form as its own step so a failure is attributable.

PROVE EVERY GATE RED BEFORE ACCEPTING IT GREEN. Plant each of the following in a
scratch copy of the catalogue, confirm the exit code is non-zero, and revert:
a `usted`-form sentence; a key present in `es` and absent from `en`; a key
present in `en` and absent from a non-empty `es`; a differing `{placeholder}`
set; and a `next/link` import beside an internal href. A gate nobody has seen
fail is a gate nobody knows works.
