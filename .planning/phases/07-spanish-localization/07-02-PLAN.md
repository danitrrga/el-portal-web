<objective>
Produce the two reference artifacts every Spanish translation in this phase is
written against: the **derived product glossary** and the **Spanish voice
contract**.

Purpose: D-01/D-02 are locked — the glossary is DERIVED from the El Portal app's
production `es.json`, never authored. The app's split is not guessable
(`Versions` translates but `Trends` and `Dashboard` stay English), so a
translator inventing terms will sell a reader "Tendencias" and then hand them an
app that says "Trends". Deriving it mechanically also means the next locale is a
data change rather than a research project.

The voice contract exists because `BRAND.md`'s anti-words list is English-only,
and `07-RESEARCH.md` §7's register rules currently live in a research document
that no translation plan is obliged to read line by line. This plan turns both
into one binding file.

Output: `src/messages/GLOSSARY.md` (a snapshot with provenance) and
`.planning/codebase/design/SPANISH-VOICE.md`. No product code is touched.
</objective>

Write `scripts/extract-glossary.mjs` — a Node script that reads the two sibling
catalogues by absolute path, flattens both to dotted key paths, and emits every
key present in both files whose English value is a short noun-phrase candidate:
one to three words, no ICU placeholders (`{`), no sentence-ending punctuation,
and starting with a capital letter or matching a known product term. Deduplicate
by the English value, and for each surviving pair emit English value, Spanish
value, the source key path, and whether the two values are identical (the
"kept English" case).

Sort output so identical-value pairs group separately from translated pairs —
the split IS the finding, and 07-CONTEXT.md D-01 warns it is not guessable.

Take the sibling repo path from an env var with the current absolute path as
default, so the script still runs if the checkout moves. The script must be
invoked by hand; it must never be wired into `npm run build`, a pre-commit hook,
or CI. D-02 is explicit: this repo does not gain a dependency on the app repo.
Read only those two JSON files — do not walk the app repo's source tree, do not
read its `.env`, and do not copy anything except English/Spanish string pairs.

Run the script and write its output into `src/messages/GLOSSARY.md` with three
sections:

  1. `## Derived from the app` — the generated table, with a provenance line
     recording the source paths, the app's next-intl version, and the extraction
     date. State plainly that this is a copied snapshot, that the app repo is
     authoritative, and that re-running the script is how it gets refreshed.
  2. `## Kept English` — the terms whose Spanish value equals the English one

     up in the app's `es.json`, never inferred from the pattern.

Cross-check the generated output against the eleven-row table in 07-CONTEXT.md
D-01. If any row disagrees, the script's filter is wrong — fix the script, do not
hand-edit the table. Record the reconciliation in the summary.

<task type="auto">
  <name>Task 2: Write the binding Spanish voice contract</name>
  <read_first>.planning/phases/07-spanish-localization/07-RESEARCH.md section 7, .planning/phases/07-spanish-localization/07-UI-SPEC.md (Copywriting Contract), .planning/codebase/design/BRAND.md, .planning/codebase/design/README.md</read_first>

  <action>
Create `.planning/codebase/design/SPANISH-VOICE.md` as a peer of the other design
docs, using the same LOCKED / CURRENT / DEBT convention documented in
`.planning/codebase/design/README.md`. It is the one file every translation plan
in Waves 2-4 reads, so it must be self-contained — a reader must not need
07-RESEARCH.md open to apply it.

Contents, all marked LOCKED:

REGISTER — reproduce 07-RESEARCH.md section 7's six priority-ordered rules
verbatim in substance, with its worked examples: never write a subject pronoun;
infinitive for CTAs, buttons and links; nominal headings where natural and `tu`
conjugation where not; `tu` conjugation for prose addressing the reader; `your X`
becomes `tu X` rather than the colder definite-article dodge; never `usted` or
formal `su` anywhere including legal copy; `vosotros` when plural address is
needed, `ustedes` never. Include the three-row right/wrong table
(`Empieza tu primera Version` / `Tu empiezas tu primera Version` /
`Empiece su primera Version`) because it is the fastest way to check a sentence.

Record explicitly that `vosotros` is ALLOWED and must never appear in a
hard-fail list — plan 07-03 builds the CI gate from this document, and including
`vosotros` there would fail the project's own sanctioned copy.

Record that `su` / `sus` is ADVISORY ONLY, because it is also the legitimate
third-person possessive ("sus tendencias"), so it warns rather than fails.

REGIONAL VARIANT — peninsular Spanish is intended; `ordenador`, `movil`, `vale`
are fine. Locale code stays `es`, not `es-ES`: the copy is Spain-flavoured but
`hreflang="es"` targets Spanish speakers everywhere, and a Latin-American reader
is better served by peninsular Spanish than by English. Note that these are two
separate decisions and must not be conflated.

CONFIRMED CTA TRANSLATIONS — the four locked strings from 07-UI-SPEC's
Copywriting Contract (`Abrir El Portal`, `Leer la metodologia`,
`Iniciar sesion`, `Crear cuenta`), with the note that all three primary-CTA call
sites wrap their label in a `text-nowrap` span, so any re-wording of those exact
strings must be re-measured against button width before merge.

SPANISH ANTI-WORDS — the list from 07-UI-SPEC verbatim (moderno, elegante,
estilizado, desatar, elevar as a verb of ambition, de ultima generacion,
revolucionario, que cambia las reglas del juego, potente/poderoso, hermoso,
inmersivo, fluido/sin fricciones as marketing filler, vanguardista, potenciar as
hype, desbloquear as hype, empoderar). State that it extends rather than replaces
BRAND.md's English list, and that both bind.

PUNCTUATION — no exclamation marks anywhere, which bans the inverted `!` in
Spanish too since it is inseparable from an exclamation; `?` questions are
permitted in prose but rare on this declarative site, and when used BOTH marks
are required (dropping the opening one to save width is not a stylistic option);
straight double quotes as today, never guillemets, because the site renders
Spanish and English chrome side by side; correctly-used em/en dashes stay, but
never as a substitute for a comma.

PRODUCT VOCABULARY — a pointer to `src/messages/GLOSSARY.md` as the single
lookup, with the rule that inventing a term is a defect and appending to the
marketing-only section is the sanctioned alternative.

Add a short "How this is enforced" section naming the two mechanisms: the CI
gate from plan 07-03, and the human read-throughs D-05/D-08 require for
`/manifesto`, `/privacy` and `/terms`.

Finally, add a one-line entry to `.planning/codebase/design/README.md`'s index if
that file lists the design docs, so the new document is discoverable the same way
the others are.
