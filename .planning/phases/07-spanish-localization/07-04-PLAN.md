<objective>
Translate the shared chrome once, and build the one genuinely new UI control this
phase introduces: the `EN / ES` language switcher.

Purpose: Navbar, Footer and CTASection appear on all eight routes, so leaving
them hardcoded would mean eight plans each re-solving the same strings. This plan
is a Wave 2 dependency of every Wave 3 translation plan for exactly that reason.

The switcher is where three locked decisions become code: D-10 (text toggle, no
flags — flags denote countries, not languages), D-11 (nav on desktop, footer
everywhere, 44px minimum inherited from Phase 5's RESP-03), and D-12 (switching
preserves the current route). D-12 is the one that breaks quietly: under
`localePrefix: "as-needed"` the English path has no prefix to strip, so a naive
string prepend leaves a stale `/es` on the English side.

Output: a `common` namespace in both locales and a switcher mounted in two
places, verified against the touch-target suite rather than assumed.
</objective>

COMPONENT KIND — the three files this plan translates are NOT all the same kind.
This is from 07-01's component-kind inventory and is verified in the current tree:

  src/components/Navbar.tsx      CLIENT  ("use client", useState/useEffect)  -> useTranslations
  src/components/Footer.tsx      CLIENT  ("use client", framer-motion)       -> useTranslations
  src/components/CTASection.tsx  SERVER  (no "use client", no hooks)         -> getTranslations

`useTranslations` from `next-intl` throws in a Server Component, and adding
`"use client"` to CTASection to make it work would ship a static marketing
section into the client bundle for no gain (07-07 makes the same call for
SystemBlueprintSection and MethodologyPreviewSection). CTASection must stay a
Server Component and use `getTranslations('common')` from `next-intl/server`.

CTASection's only link is the absolute `APP_URL` external link, so it has NO
internal `Link` to migrate — the `@/i18n/navigation` swap applies to Navbar and
Footer only.

The switcher itself is a Client Component (it reads `useLocale` and the
client-side `usePathname`), so it may be mounted directly inside Navbar and
Footer without changing their kind.

Locked switcher spec (07-UI-SPEC "Language Switcher"):
  markup      two Links with a static "/" separator between them
  active      text-[var(--color-ep-fg-strong)] + aria-current="page"
  inactive    text-[var(--color-ep-fg)] hover:text-[var(--color-ep-fg-strong)] transition-colors duration-300
  separator   text-[var(--color-ep-fg-subtle)], non-interactive
  chrome      no border, no pill background, no badge, no blue accent
  navbar      inside the Right Actions cluster, BEFORE "Log in", wrapped hidden md:flex items-center
  footer      third flex child of the bottom bar, between the copyright and the wordmark
  target      min-h-11 md:min-h-0 on EACH link individually, not on the group

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| catalogue -> rendered chrome | translated values become nav, footer and CTA content on every route |
| client -> locale cookie | the switcher causes a locale preference to be persisted |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-04-01 | Tampering | catalogue strings rendered in Navbar/Footer/CTASection | mitigate | Values render as React text nodes via `useTranslations`/`getTranslations`; no `dangerouslySetInnerHTML` is introduced, so a catalogue edit cannot inject markup |
| T-07-04-02 | Spoofing | switcher href construction | mitigate | Targets come from next-intl's `Link` with an explicit locale and the unprefixed `usePathname`, both derived from the current route; no user-supplied value reaches an href |
| T-07-04-03 | Information disclosure | `NEXT_LOCALE` written on switch | accept | Two-letter UI preference only; no identity, no session meaning. Attributes are set in 07-01 (`sameSite: lax`, `path: /`) |
| T-07-04-04 | Tampering | external `APP_URL` links | mitigate | External links stay on `next/link` with absolute origins so they are never locale-prefixed into a broken internal path; Gate 3 enforces the split |
| T-07-04-05 | Information disclosure | server-only code pulled into the client bundle | mitigate | CTASection stays a Server Component on `getTranslations`; the Task 2 gate fails if `"use client"` or `useTranslations` appears in that file |
| T-07-04-SC | Tampering | package installs | accept | This plan installs nothing; the switcher is hand-built from Link plus Tailwind, and 07-UI-SPEC forbids pulling a registry "language switcher" block |
</threat_model>
