<objective>
Translate the shared chrome once, and build the one genuinely new UI control this
phase introduces: the `EN / ES` language switcher.

Purpose: Navbar, Footer and CTASection appear on all eight routes, so leaving
them hardcoded would mean eight plans each re-solving the same strings. This plan
is a Wave 2 dependency of every Wave 3 translation plan for exactly that reason.

The switcher is where three locked decisions become code: D-10 (text toggle, no
flags — flags denote countries, not languages), D-11 as revised 2026-08-19
(nav on EVERY viewport — the desktop actions row above 768px and the hamburger
panel below it — plus the footer as the bottom-of-page fallback, 44px minimum
inherited from Phase 5's RESP-03), and D-12 (switching preserves the current
route). D-12 is the one that breaks quietly: under
`localePrefix: "as-needed"` the English path has no prefix to strip, so a naive
string prepend leaves a stale `/es` on the English side.

D-11's 44px is the one that breaks LOUDLY, and the cross-AI review caught it
before execution: the obvious implementation (`min-h-11` alone, copied from the
Footer's existing links) guarantees height and not width, and
`e2e/touch-targets.spec.ts` asserts both. See the TOUCH TARGET CONTRACT in
`<interfaces>` — that block is the whole reason this plan was revised.

The switcher also carries the fix for a defect the second cross-AI review found
and three prior checker passes missed: choosing EN from `/es` navigates to the
unprefixed `/`, the `/` negotiation reads the still-`es` cookie, and the reader
is bounced straight back to `/es`. English is unreachable through the site's own
control. The switcher — not the proxy — is what persists an explicit choice, and
the CLIENT-SIDE LOCALE CHOICE PATH in `<interfaces>` is the single place that
writes locale state.

Output: a `common` namespace in both locales, a switcher mounted in three
places, and a fixed-position cross-locale hint — all verified against the
touch-target suite rather than assumed.
</objective>

CLIENT-SIDE LOCALE CHOICE PATH — ONE place writes locale state, and it is the
switcher. Read this before writing Task 1.

  On activating a locale link, and BEFORE navigation begins, write exactly two
  cookies with `document.cookie`:

    NEXT_LOCALE=<selected locale>; path=/; max-age=31536000; samesite=lax
    NEXT_LOCALE_HINT=; path=/; max-age=0

  The first is the fix for the English-unreachable loop. `src/proxy.ts` (07-01)
  negotiates at `/` and reads `NEXT_LOCALE` there; it never writes it. So a
  reader on `/es` clicking EN navigates to the unprefixed `/`, and unless the
  cookie already says `en` by then, the proxy sends them back to `/es` forever.
  The write must precede the navigation, not follow it.

  The second clears the hint's dismissal (`NEXT_LOCALE_HINT=off`, written by
  LocaleHint). Dismissal is permanent otherwise, so a reader who dismissed the
  hint and later switches language would never see it again even in a genuinely
  new situation. Expiring it here — rather than in LocaleHint — is why this is
  called one path: a single handler owns every cookie the phase writes.

  Mechanism: keep the locale `Link` from `@/i18n/navigation` for markup and
  semantics (it is what makes D-12 correct under `as-needed`, and it preserves
  middle-click and open-in-new-tab), and attach an `onClick` handler that writes
  both cookies and then calls `onNavigate?.()`. `document.cookie` writes are
  synchronous, so both cookies are set before Next's router issues the RSC
  request. VERIFY that empirically against the production build rather than
  trusting it: from `/es`, click EN, and confirm the final URL is `/` and
  `document.cookie` contains `NEXT_LOCALE=en`. If a bounce back to `/es` is
  observed, escalate to `event.preventDefault()` followed by
  `router.replace(pathname, { locale })` using `useRouter` from
  `@/i18n/navigation`, and record the escalation in the summary.

From 07-01:
  src/i18n/navigation.ts -> { Link, redirect, usePathname, useRouter, getPathname }
  `usePathname` from this module returns the pathname WITHOUT the locale prefix,
  which is what makes a route-preserving switch a one-liner under `as-needed`.
  src/messages/{en,es}/common.json exist as `{}` and are owned solely by this plan.

`if (r.width >= min && r.height >= min) continue;` — BOTH dimensions of
`getBoundingClientRect()`, never one. Line 49 is
`test.skip(width >= 768, ...)`, so every `md:` variant is invisible to this
spec: the only rendering it ever measures is below 768px, which is the FOOTER

It exempts an anchor only when the anchor's own PARENT contains a non-whitespace
TEXT NODE. This switcher's `/` separator is an `aria-hidden` ELEMENT (required,
see Task 1), so the parent holds only elements and whitespace, the exemption
never fires, and both dimensions are measured.

width 22 => the spec pushes an offender and CI goes red on `touch-iphone`.

SIZING — this is the part the cross-AI review found broken, so implement the
mechanism, not the intent. Apply
`flex min-h-11 min-w-11 items-center justify-center px-3 md:min-h-0` to EACH of
the two links individually, never to the wrapping group. Every class in that
string is load-bearing:
  min-h-11        supplies the 44px height
  px-3            supplies 12px of padding on each side, which is what actually
                  pushes the measured WIDTH of a ~22px "EN" past 44px; padding
                  is the mechanism because it grows the link's own border box,
                  which is what `getBoundingClientRect()` returns
  min-w-11        is the floor guarantee for the case where a font metric or a
                  future label renders narrower than assumed; it applies to the
                  link's own box, so it goes on the link and never on the flex
                  parent (a parent's min-width does not force a child's width)
  justify-center  centres the label inside that box
  md:min-h-0      restores a compact desktop row, mirroring the Footer's
                  existing precedent. It is safe only because the spec skips at
                  `width >= 768` and never measures the desktop rendering.
Do NOT revert `px-3` or `min-w-11` at any breakpoint. The switcher is new UI, so
there is no frozen desktop rendering to preserve, and a consistent hit area is
worth 12px of gutter in the nav row.

nameless generic container is dropped by most screen readers. The label text is
translated because it is user-facing; the `EN`/`ES` codes are not.
