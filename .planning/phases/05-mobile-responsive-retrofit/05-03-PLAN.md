F-changelog-overflow CONFIRMED — `/changelog`: `documentElement.scrollWidth = 388` vs
`clientWidth = 361` — **27px of real page overflow**. The per-element sweep found NOTHING, so the
cause is not an oversized box. Per AUDIT-BRIEF.md: "trust the root assertion; use the sweep to
locate, not to decide."

Arithmetic that identifies the changelog culprit (verify before assuming):
`<main>` on `src/app/changelog/page.tsx:902` is `mx-auto w-full max-w-5xl px-6` -> content box at
361px = 361 - 48 = **313px**. Overflow to 388 implies the overflowing run is 388 - 24 = **364px**
wide. The H1 on line 905-913 is a single word, `Changelog`, rendered by the `.display` utility
(Special Gothic Expanded One, `text-transform: uppercase`) at an inline
`fontSize: "clamp(48px, 6vw, 80px)"`. At 360px, `6vw` = 21.6px so the clamp floor of 48px
applies. Nine glyphs of an *expanded* display face at 48px measure ~364px. A single word has no
wrap opportunity, so it overflows its block box without inflating the element's
`getBoundingClientRect()` — exactly the "text node overflowing its container" case that defeats
the element sweep.

Tailwind v4.2.1 arbitrary-value syntax rule (RESEARCH.md section 1): arbitrary values **must not
contain spaces**, including after commas. `text-[clamp(2rem,3.92vw+1.12rem,3rem)]` compiles;
`text-[clamp(2rem, 3.92vw + 1.12rem, 3rem)]` silently does not.

RESPONSIVE.md fluid-type rules that any new clamp must satisfy:
1. the `+ Nrem` term is mandatory (browsers do not scale `vw` on zoom -> WCAG 1.4.4)
2. `max <= 2.5 x min`

`overflow-x: clip` vs `hidden` (05-CONTEXT.md, locked): clipping is permitted on a **specific
wrapper**, never on `body`. `clip` does not create a scroll container and does not break
`position: sticky`. When `overflow-x: clip` is set and `overflow-y` is `visible`, `overflow-y`
stays `visible` (unlike with `hidden`, which forces the other axis to `auto`). `overflow`
values other than `visible` do not clip `position: fixed` descendants unless the element also has
a `transform`/`filter`/`will-change` — `ReadingLayout`'s root has none, so the `fixed inset-0`
grain and grid overlays on lines 17-33 are unaffected.

`e2e/overflow.spec.ts` behaviour: the per-element sweep skips any element whose ancestor has
`overflowX !== "visible"`, then asserts `documentElement.scrollWidth <= clientWidth + 1` and
`body.scrollWidth <= clientWidth + 1` as a backstop. `e2e/support/pages.ts` force-applies
`html, body { overflow-x: visible !important }` during the probe, so `<body>`'s current
`overflow-x-hidden` does not mask anything from the harness.
