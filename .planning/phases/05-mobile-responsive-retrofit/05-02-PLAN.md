<objective>
Bring every interactive target on the two global surfaces (Navbar, Footer) and the shared
`Button` primitive up to 44x44 CSS px below 768px, without changing a single pixel of the
approved desktop rendering.

into one systemic lever — the `size` variants in `buttonVariants`. Fixing that one file resolves
the Hero CTAs, the CTA section, the methodology link, the MCP link, the pricing CTA and both
Navbar buttons at once. What remains are five hand-rolled targets.

Output: mobile-first size variants in `src/components/ui/button.tsx`, a `Button`-based Navbar
hamburger, 44px mobile-menu rows, 44px wordmark links in nav and footer, a 44px `CopyButton` on
phones, and a one-line correction to the touch-target spec's skip boundary.
</objective>

- `default`: `h-9 px-4 py-2 has-[>svg]:px-3`
- `xs`: `h-6 gap-1 rounded-md px-2 text-xs has-[>svg]:px-1.5 [&_svg:not([class*='size-'])]:size-3`
- `sm`: `h-8 rounded-md gap-1.5 px-3 has-[>svg]:px-2.5`
- `lg`: `h-10 rounded-md px-6 has-[>svg]:px-4`
- `icon`: `size-9`
- `icon-xs`: `size-6 rounded-md [&_svg:not([class*='size-'])]:size-3`
- `icon-sm`: `size-8`
- `icon-lg`: `size-10`

`buttonVariants` base string contains `[&_svg:not([class*='size-'])]:size-4`. This CSS rule
overrides lucide's `size={N}` HTML width/height attributes. Any icon inside a `Button` that must
NOT be 16px needs an explicit `size-*` class on the icon element.

Available `Button` variants: `default`, `destructive`, `outline`, `secondary`, `ghost`, `link`,
`brand`, `brand-link`. CLAUDE.md forbids `default` and `ghost` for hero/nav CTAs.

`e2e/touch-targets.spec.ts` behaviour:
- `AAA_TARGET = 44`
- line 23: `test.skip(width > 768, "AAA touch target applies to touch-sized viewports")`
- it measures `el.getBoundingClientRect()` of the element itself, so an `::after` hit-area
  overlay does NOT satisfy it — the element box must actually be 44x44
- links matching `el.closest("p, li")` are exempt (SC 2.5.8 inline exception), which is why the
  Footer link columns (inside `<li>`) are already out of scope
- selector set: `a[href], button, [role="button"], input, select, textarea, [tabindex]:not([tabindex="-1"])`

Playwright project reality (this is the trap): the `reflow-320` / `mobile-360` / `mobile-390` /
`mobile-430` / `tablet-768` projects spread `devices["Desktop Chrome"]` and only override
`viewport`. They have `hasTouch: false`, so **`@media (pointer: coarse)` does NOT match in
them**. A `pointer-coarse:` upsize would silently fail every one of those projects. Fixes here
MUST be viewport-gated (`md:`), not pointer-gated. Only the `touch-iphone` project is a real
touch device.

Measured baseline at `mobile-360` (SURFACES.md, harness-verified 2026-07-30):
Navbar hamburger 20x20 · nav wordmark link 98x24 · footer wordmark link 98x26 ·
"Sign Up" CTA 80x32 · `CopyButton` 28x28 · mobile menu rows ~34px tall
