  <action>
    In each of the eight files, replace the single token `min-h-screen` with `min-h-viewport` at
    the line listed in `<interfaces>`. Change nothing else in those className strings — keep
    `relative`, `w-full`, the `bg-*` tokens and the ordering exactly as they are. There is exactly
    one `min-h-screen` per file; `grep -rn "min-h-screen" src` must return zero hits afterwards.

    Why: `min-h-screen` compiles to a bare `min-height: 100vh`, and on iOS Safari `vh` resolves to
    the *large* viewport (address bar retracted), so with the bar expanded the bottom of a
    full-height section sits below the fold on load. `min-h-viewport` emits
    `min-height: 100vh` then `min-height: 100svh`, giving the small-viewport value on modern
    browsers and the legacy value on the ~5% without `svh` support.

    Do not use `dvh`: it re-resolves during the address-bar animation, and because scrolling is
    not treated as user input for CLS purposes those shifts are charged in full.
    Do not use the built-in `min-h-svh` utility — it emits only one declaration and drops the
    fallback that RESP-05 requires.

    Note: DevTools/Playwright emulation cannot reproduce iOS address-bar behaviour, so this fix is
    verified structurally (the compiled CSS carries both declarations) rather than behaviourally.
    Flag it in the summary as needing a real-device pass.
  </action>

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-11 | Information Disclosure | residual-fix pressure to add `overflow-x-hidden` / `clip` to a page | mitigate | Clipping content to pass a test can hide information and fail WCAG 1.4.10. Task 3 forbids it outright except on `pointer-events-none` decoration, with a grep-based acceptance criterion |
