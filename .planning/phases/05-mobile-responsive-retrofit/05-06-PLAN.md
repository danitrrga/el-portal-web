Create `e2e/containment.spec.ts`. Import `{ test, expect }` from `@playwright/test` and
`{ ROUTES, gotoSettled }` from `./support/pages`. Call
`test.describe.configure({ mode: "parallel" })`. Emit one `test()` per entry in `ROUTES`,
titled `container-relative overflow: ${route}`.

Each test calls `await gotoSettled(page, route)` and then a **single** `page.evaluate` that
walks `document.body.querySelectorAll("*")` and returns
`{ textOverflow: TextOverflow[], clipEscape: ClipEscape[] }`. Declare both result types at
module scope so `tsc -p tsconfig.e2e.json` type-checks them.

**Shared exclusion predicate `isExcluded(el)`** returns `true` when any of the following
hold. Each line is load-bearing and was verified during planning to remove a specific, named
false positive without removing any target:
1. `el.namespaceURI !== "http://www.w3.org/1999/xhtml"` — SVG child rects are painted
   geometry, not layout boxes; measuring `<g>`/`<path>` against a layout viewport is
   meaningless and produced 3-6px noise on `/`.
2. `el.closest("[data-reflow-exempt]")` — RESPONSIVE.md's sanctioned 2-D-layout marker.
3. `el.closest('[aria-hidden="true"]')` — decorative subtrees, e.g. the Footer wordmark
   (`src/components/Footer.tsx:116`) and the Hero atmosphere layers.
4. computed `display === "none"`, `visibility === "hidden"`, or `opacity === "0"`.
5. computed `position === "fixed"` — a fixed element's containing block is the viewport, so
   comparing it against an ancestor is meaningless (`src/components/ReadingLayout.tsx` has
   two `fixed inset-0` overlays inside an `overflow-x-clip` wrapper).
6. **Presentational overlay:** computed `position === "absolute"` **and** computed
   `pointerEvents === "none"` **and** `el.children.length === 0` **and** trimmed
   `textContent` is empty. This is the guard that exempts `ReadingLayout.tsx:14`'s
   `w-full md:w-[1200px]` glow, which deliberately escapes its `overflow-x-clip` wrapper by
   216px at tablet-768 and 88px at laptop-1024 on `/privacy` and `/terms`. It carries no
   content, so nothing is lost by clipping it.

**Sweep A — `textOverflow`: text wider than its own box.** This is the check that sees a
defect regardless of how many clipping ancestors sit above it. Consider an element only
when: `!isExcluded(el)`; `el.children.length === 0`; trimmed `textContent` is non-empty;
computed `display !== "inline"` (an inline non-replaced box reports `clientWidth === 0` and
would produce garbage); computed `overflowX` is neither `"auto"` nor `"scroll"`; and
computed `textOverflow !== "ellipsis"` (Tailwind's `truncate` is an author-declared,
user-visible truncation affordance, not a defect — this guard removes three
`span.text-[13px].font-medium.truncate` offenders on `/` at 320px). Flag when
`el.scrollWidth > el.clientWidth + 1`. Record
`{ selector, scrollWidth, clientWidth, overflowBy, fontSize, height, text }` where
`overflowBy` is `el.scrollWidth - el.clientWidth`, `height` is the rounded
`getBoundingClientRect().height`, and `text` is the first 60 characters of the trimmed text.

**Sweep B — `clipEscape`: content that is off-screen but masked by a clipping ancestor.**
This is the exact complement of `overflow.spec.ts`'s `isClippedByAncestor` skip: it collects
precisely the elements that spec deliberately discards. Consider an element only when
`!isExcluded(el)` and its rect has non-zero area. Compute
`offscreenBy = Math.round(Math.max(r.right - vw, -r.left))` where `vw` is
`document.documentElement.clientWidth`; skip unless `offscreenBy > 2` (2px, not 1px, for the
float32 transform quantisation documented in this phase's CR-01 fix). Then walk
`p = el.parentElement` upward, stopping at `document.body`, recording **every** ancestor
whose computed `overflowX !== "visible"` — keep both the nearest and the outermost. Skip the
element if there is no such ancestor (that is viewport-level overflow, which
`overflow.spec.ts` already owns) or if the **nearest** one has `overflowX` of `"auto"` or
`"scroll"` (a legitimate self-scrolling container per RESPONSIVE.md — this is what exempts
`<pre>` code blocks on `/mcp`). Record
`{ selector, clipper, nearestClipper, elLeft, elRight, viewportWidth, offscreenBy }`, where
`clipper` is `describe(outermostClipper)` and `nearestClipper` is `describe(nearestClipper)`.

Reporting both clippers matters: for the GAP-02 `img`, the *nearest* clipper is
`div.relative.mx-auto.max-w-6xl` (which the image legitimately fits inside), while the
*outermost* is `section.relative.overflow-hidden` — the ancestor GAP-03 actually names. A
nearest-only formulation cannot see this and was measured returning zero offenders.

Sort both arrays descending by `overflowBy` / `offscreenBy` and `slice(0, 15)`, matching
`overflow.spec.ts`'s reporting convention.
