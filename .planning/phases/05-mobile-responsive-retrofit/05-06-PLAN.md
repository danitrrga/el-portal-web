<objective>
Close **GAP-03**: the responsive harness is blind to container-relative overflow.

`e2e/overflow.spec.ts` asserts on `document.documentElement.scrollWidth` and explicitly
*skips* any element clipped by an ancestor (`isClippedByAncestor`, lines 40-49). That skip
is correct for its own question ("does the page scroll sideways?") but it means
`section.relative.overflow-hidden` in `src/components/Hero.tsx:34` absorbs both GAP-01 and
GAP-02 and the suite reports green. This is the exact defect class RESP-02 was written to
kill (`overflow-x-hidden` on `<body>`), reproduced one level down the tree.

Purpose: make a defect hidden behind a clipping ancestor fail automatically, and prove it
by leaving the suite **red against the current, unfixed `src/`**. Plan 05-07 turns it green.
This ordering is the proof that the harness gap is genuinely closed rather than merely
asserted.

Output: `e2e/containment.spec.ts`, wired into `playwright.config.ts` and `package.json`,
plus a recorded RED baseline and a triaged offender inventory.
</objective>

  <action>
Create `e2e/containment.spec.ts`. Import `{ test, expect }` from `@playwright/test` and
`{ ROUTES, gotoSettled }` from `./support/pages`. Call
`test.describe.configure({ mode: "parallel" })`. Emit one `test()` per entry in `ROUTES`,
titled `container-relative overflow: ${route}`.

Each test calls `await gotoSettled(page, route)` and then a **single** `page.evaluate` that
walks `document.body.querySelectorAll("*")` and returns
`{ textOverflow: TextOverflow[], clipEscape: ClipEscape[] }`. Declare both result types at
module scope so `tsc -p tsconfig.e2e.json` type-checks them.

Shared skip predicate `isExcluded(el)` returns `true` when any of the following hold:
`el.closest("[data-reflow-exempt]")` is non-null; `el.closest('[aria-hidden="true"]')` is
non-null; computed `display === "none"`; computed `visibility === "hidden"`; computed
`opacity === "0"`; computed `position === "fixed"`. The `position: fixed` exclusion is
load-bearing — a fixed element's containing block is the viewport, so comparing its rect
against an ancestor's rect is meaningless (`src/components/ReadingLayout.tsx` has two
`fixed inset-0` overlays inside an `overflow-x-clip` wrapper that would otherwise be
permanent false positives).

**Sweep A — `textOverflow`: text wider than its own box.** This is the check that catches a
defect regardless of how many clipping ancestors sit above it. Consider an element only
when: `!isExcluded(el)`; `el.children.length === 0`; `(el.textContent ?? "").trim().length > 0`;
computed `display` is not `"inline"` (an inline non-replaced box reports `clientWidth === 0`
and would produce garbage); computed `overflowX` is neither `"auto"` nor `"scroll"`. Flag
when `el.scrollWidth > el.clientWidth + 1`. Record
`{ selector, scrollWidth, clientWidth, overflowBy, fontSize, text }` where `selector` comes
from the `describe(el)` helper, `overflowBy` is `el.scrollWidth - el.clientWidth`,
`fontSize` is `getComputedStyle(el).fontSize`, and `text` is the first 60 characters of the
trimmed text content.

**Sweep B — `clipEscape`: perceivable content extending past its nearest clipping ancestor.**
Consider an element only when `!isExcluded(el)` AND it is content-bearing, defined as
`el.matches("img, svg, video, canvas, a, button, input, select, textarea, summary, [role='button']")`
OR (`el.children.length === 0` AND `(el.textContent ?? "").trim().length > 0`). Restricting
to content-bearing elements is what keeps the sweep honest: an empty `<div>` used to paint a
radial gradient or a grain overlay is *supposed* to be clipped, and flagging it would drown
the real signal.

For each candidate, walk `p = el.parentElement` upward, stopping at `document.body`, and
take the first ancestor whose computed `overflowX !== "visible"`. Skip the element if there
is no such ancestor (viewport-level overflow is `overflow.spec.ts`'s job, not this spec's)
or if that ancestor's `overflowX` is `"auto"` or `"scroll"` (a legitimate scroll container
per RESPONSIVE.md's reflow rules — this is what exempts `<pre>` code blocks on `/mcp`).
Compare `el.getBoundingClientRect()` against the clipper's `getBoundingClientRect()` and
flag when `r.right > clipRect.right + 2` or `r.left < clipRect.left - 2`. The 2px tolerance
(not 1px) accounts for the float32 transform quantisation documented in this phase's CR-01
fix. Record `{ selector, clipper, elLeft, elRight, clipLeft, clipRight, escapedBy }` where
`clipper` is `describe(clipAncestor)` and `escapedBy` is
`Math.round(Math.max(r.right - clipRect.right, clipRect.left - r.left))`.

Sort both arrays widest-first by `overflowBy` / `escapedBy` and `slice(0, 15)`, matching
`overflow.spec.ts`'s reporting convention.

At module scope, declare and export
`const KNOWN_UNFIXED: { route: string; selector: string; reason: string; ref: string }[] = []`.
Filter both offender arrays through it before asserting: an offender is suppressed when its
`route` matches and its `selector` starts with the entry's `selector`. Every entry's `ref`
must name a heading that exists in
`.planning/phases/05-mobile-responsive-retrofit/deferred-items.md`. Leave the array **empty**
in this task; Task 2 populates it only where triage proves an entry is warranted. Add a
comment above it stating that an entry is debt made visible, never a way to silence a defect
this phase owns.

Attach each non-empty array via `testInfo.attach` as `contentType: "application/json"`
(names `text-overflow-offenders` and `clip-escape-offenders`), then assert
`expect(textOverflow, \`Text wider than its own container on ${route}\`).toEqual([])` and
`expect(clipEscape, \`Content escaping a clipping ancestor on ${route}\`).toEqual([])`.

In `playwright.config.ts`, change line 24 from
`const LAYOUT_SPECS = /(overflow|a11y|touch-targets)\.spec\.ts/;` to
`const LAYOUT_SPECS = /(overflow|containment|a11y|touch-targets)\.spec\.ts/;`. Change
nothing else in that file — not the viewport table, not the projects, not the webServer
block.

In `package.json`, add `"audit:containment": "playwright test containment.spec.ts"`
immediately after the existing `"audit:overflow"` entry. Do not reorder or alter any other
script.

Do not modify `e2e/overflow.spec.ts`, `e2e/support/pages.ts`, or any file under `src/`.
  </action>
